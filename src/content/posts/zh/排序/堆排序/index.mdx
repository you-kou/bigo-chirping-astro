**堆排序（Heap Sort）** 是一种基于比较的排序算法，利用 **二叉堆（Binary Heap）** 这种数据结构来实现。它的核心思想是将无序数组构造成一个堆，通过不断取出堆顶元素（最大值或最小值），从而达到排序的目的。

堆排序的时间复杂度固定为 $O(n \log n)$，且是一种**原地排序算法**（不需要额外的辅助空间）。

## 什么是堆？

[堆](/posts/%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84/%E5%A0%86/)是一种特殊的**完全二叉树**，在逻辑上是树形结构，在物理上通常用**连续的数组**来存储。

- **最大堆（大顶堆）：** 每个节点的值都**大于或等于**其左右子节点的值。即 `arr[i] >= arr[2i+1]` 且 `arr[i] >= arr[2i+2]`。**用于升序排序**。
- **最小堆（小顶堆）：** 每个节点的值都**小于或等于**其左右子节点的值。即 `arr[i] <= arr[2i+1]` 且 `arr[i] <= arr[2i+2]`。**用于降序排序**。

<Callout type="info" title="">
**数组索引映射规则**（设节点索引为 `i`，从 `0` 开始）：

- 父节点：`parent = (i - 1) / 2`
- 左子节点：`left = 2 * i + 1`
- 右子节点：`right = 2 * i + 2`

## 堆排序的基本原理

以升序排序（构建大顶堆）为例，堆排序分为两个核心阶段：

### 阶段一：建堆（Build Heap）

把无序的原始数组构建成一个**大顶堆**。

1. 从最后一个非叶子节点开始（索引为 `n/2 - 1`）。
2. 从右到左、从下到上依次对每个节点执行**下沉调整（Heapify）**，确保每个子树都满足大顶堆性质。

1. 将堆顶元素（此时数组的最大值，即 `arr[0]`）与当前堆的最后一个元素交换。

## 代码实现

```c++
#include <iostream>
#include <vector>
using namespace std;

void heapify(vector<int>& arr, int n, int i) {
    int largest = i;
    int left = 2 * i + 1;
    int right = 2 * i + 2;

    if (left < n && arr[left] > arr[largest])
        largest = left;

    if (right < n && arr[right] > arr[largest])
        largest = right;

    if (largest != i) {
        swap(arr[i], arr[largest]);
        heapify(arr, n, largest);
    }
}

void heapSort(vector<int>& arr) {
    int n = arr.size();

    // 建堆
    for (int i = n / 2 - 1; i >= 0; i--)
        heapify(arr, n, i);

    // 排序
    for (int i = n - 1; i > 0; i--) {
        swap(arr[0], arr[i]);
        heapify(arr, i, 0);
    }
}
```

## 复杂度与特性分析

| **维度**           | **分析 / 结论** | **说明**                                               |
| ------------------ | --------------- | ------------------------------------------------------ |
| **最好时间复杂度** | $O(n \log n)$   | 即使原数组有序，建堆与调整的总体开销仍为 $O(n \log n)$ |
| **最坏时间复杂度** | $O(n \log n)$   | 任何情况下都需要经历完整的建堆和 $n-1$ 次调整          |
| **平均时间复杂度** | $O(n \log n)$   | 性能非常稳定                                           |
| **空间复杂度**     | $O(1)$          | 原地排序，仅需常数级别的变量空间（迭代实现时）         |
| **稳定性**         | **不稳定排序**  | 在堆顶与堆尾交换时，可能会破坏相同元素的相对顺序       |

## 优缺点与适用场景

### 优点

1. **稳定高效：** 无论数据初始状态如何，时间复杂度始终锁定在 $O(n \log n)$，不会像快速排序那样退化到 $O(n^2)$。
2. **空间占用极低：** 属于原地排序，不需要额外的数组空间。

### 缺点

1. **CPU 缓存不友好：** 堆排序依赖父子节点跳跃式的访问（例如从索引 `i` 跳转到 `2i+1`），这会导致较高的 CPU Cache Miss（缓存未命中）率。因此在实际工程中，整体速度通常慢于**快速排序**。
2. **不稳定：** 不适用于要求保持等值元素相对顺序的场景。

### 典型应用场景

- **Top-K 问题：** 在大量数据（如 10 亿个数据）中找出前 K 个最大/最小的元素。此时不需要对全部数据排序，仅维护一个大小为 K 的堆即可，空间复杂度降至 $O(K)$。
- **优先队列（Priority Queue）：** C++ 的 `std::priority_queue` 和 Java 的 `PriorityQueue` 底层均由堆结构实现。
