**哈希表（Hash Table）**，也叫**散列表**，是计算机科学中最核心的数据结构之一。如果把数组比作“按编号找人”，那哈希表就是“按名字直接找人”。

它的核心优势在于：**极快**。在理想情况下，插入、查找和删除的时间复杂度都是 **$O(1)$**（即常数时间，无论数据量多大，几乎瞬间完成）。

## 哈希表是怎么工作的？

哈希表的核心秘密在于：利用**映射函数**把复杂的查找转变为直接的数组下标访问。

它主要由两部分组成：

1. **键值对（Key-Value Pair）：** 你存入的数据。比如用 `Key` 存用户名，用 `Value` 存用户的详细资料。
2. **哈希函数（Hash Function）：** 一个数学公式。你给它一个 `Key`（比如字符串 `"apple"`），它会计算出一个整数数字（比如 `3`）。这个数字就是底层数组的下标（Index）。

## 核心难题：哈希冲突（Hash Collision）

理想很美好，但数组大小是有限的，而 Key 的组合是无限的。如果不同的 Key 计算出了相同的下标，就会发生**哈希冲突**（比如 `"apple"` 和 `"banana"` 算出来的索引都是 `3`）。

解决冲突主要有两种最经典的策略：

### ① 拉链法（Chaining / 链表法）

- **原理：** 数组的每个位置不直接存数据，而是挂一个**链表**（或者红黑树）。
- **处理过程：** 冲突发生时，把新的键值对直接挂在对应位置的链表末尾。
- **代表语言：** Java 中的 `HashMap`、C++ 中的 `std::unordered_map`。

### ② 开放寻址法（Open Addressing）

- **原理：** 如果算出来的坑位已经被占了，就按照某种规则往后找下一个**空的坑位**。
- **探查方式：** 比如**线性探测**（挨个看下一个坑）、**二次探测**或**双重哈希**。
- **代表语言：** Python 中的 `dict`。

## 为什么哈希表这么快？

- **普通数组：** 按索引查 $O(1)$，按值查 $O(n)$（要挨个找）。
- **链表：** 查任何元素都是 $O(n)$。
- **平衡二叉树：** 查找需要 $O(\log n)$。
- **哈希表：** 借助哈希函数，一步到位算出存储地址，直接定位，因此是 **$O(1)$**。

> **什么时候会变慢？**
>
> 当装载因子（Load Factor = 已存元素数 / 数组容量）过高，或者哈希函数设计得很糟糕导致大量冲突时，哈希表会退化成链表，查找效率会降为 **$O(n)$**。因此，哈希表会在空间不够时自动触发**扩容（Rehash）**。

## 各编程语言中的“哈希表”

虽然底层原理一致，但在不同语言里它的名字不太一样：

| **语言**       | **对应实现/名称**    |
| -------------- | -------------------- |
| **C++**        | `std::unordered_map` |
| **Java**       | `HashMap`            |
| **Python**     | `dict`（字典）       |
| **JavaScript** | `Object` / `Map`     |
| **Go**         | `map`                |

## 优点与局限性

### 优点

- ⚡ **极速读写：** 插入、删除、查询在平均情况下均为 $O(1)$。
- 🔑 **灵活的 Key：** 可以用字符串、对象等任意能计算哈希值的类型作为索引。

### 局限性

- ❌ **无序性：** 传统的哈希表内部元素是无序存放的（Python 3.7+ 的 dict 通过附加索引数组实现了按插入顺序排列，但底层依然不按 Key 排序）。
- ❌ **范围查询极慢：** 无法高效地进行“查找大于 10 且小于 50 的所有元素”这种操作（这种场景通常用 **B+ 树** 或 **红黑树**）。
- ❌ **内存开销较多：** 需要预留额外的数组空间来降低冲突概率。
