**数组（Array）** 是计算机科学中最基础、最核心的**线性数据结构**（Linear Data Structure）。它用一块**连续的内存空间**，来存储一组具有**相同类型**的数据。

## 核心特性与内存布局

数组最核心的两大特点：**内存连续分配**、**存储元素类型完全相同**。

以 C++ 的`int`数组为例，`int`类型每个元素占用 4 字节。当定义整型数组时，全部元素会在内存里紧密相邻、依次排布。

### 寻址公式：为什么下标通常从 0 开始？

因为数组在内存中是连续存放的，计算某个元素的物理内存地址非常高效：

$$\text{Address}(i) = \text{BaseAddress} + i \times \text{ElementSize}$$

- **$\text{BaseAddress}$**：数组起始内存地址（即下标为 `0` 的地址）。
- **$\text{ElementSize}$**：单个元素占用的内存字节数（如 `int` 占用 4 字节）。
- **下标 $i$ 的本质**：表示该元素相对于首地址的**偏移量（Offset）**。如果从 `0` 开始，寻址公式只需一次乘法和一次加法。

## 常见操作与时间复杂度

| **操作**              | **时间复杂度** | **机制与原因**                                               |
| --------------------- | -------------- | ------------------------------------------------------------ |
| **随机访问 (Access)** | $O(1)$         | 通过寻址公式直接计算物理内存地址，一步到位                   |
| **按值查找 (Search)** | $O(n)$         | 无序数组需要逐个遍历；若已排序，二分查找可优化至 $O(\log n)$ |
| **末尾插入 / 删除**   | $O(1)$         | 直接在末尾操作，不需要移动其他元素                           |
| **中间插入 / 删除**   | $O(n)$         | 为保持连续性，插入时需将后续元素向后平移；删除时需向前平移   |

## 优缺点分析

### 优点

- **超高读取效率**：支持根据下标 $O(1)$ 随机访问。
- **CPU 缓存友好（Cache Locality）**：因为数据连续存放，CPU 预取机制会将其批量加载到 Cache，大幅提升访问性能。
- **空间利用率高**：不需要像链表那样额外存储指向下一个元素的指针。

### 缺点

- **插入/删除成本高**：平均需要平移一半的元素（$O(n)$）。
- **空间连续性要求高**：如果内存碎片严重，即使剩余总内存足够，也可能因为找不到足够大的**连续内存**而分配失败。

## 适用场景

- **频繁查询，极少增删**：如存储一周 7 天的名称、常量对照表、查找表。
- **多维数据建模**：如矩阵运算、图像像素数据（二维数组/RGB 三维数组）。
- **作为其他数据结构的底层实现**：栈（Stack）、队列（Queue）、哈希表（Hash Table）、堆（Heap）等很多复杂数据结构都是基于数组构建的。
